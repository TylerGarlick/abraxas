# Plan: Transition from Probabilistic Prompting to Deterministic Infrastructure

## 🎯 Objective
Convert the "Sovereign" capabilities of Abraxas from LLM-simulated behaviors (prompts) into a hard-coded, deterministic verification pipeline. The goal is to ensure that the **Sovereign Seal** is a verifiable artifact of a process, not a stylistic choice by the model.

## 🏗️ Architectural Shift: The "Sovereign Engine"

### 1. From Weights to Vault (The Truth Anchor)
**Current State**: I "remember" truths based on context windows and memory files.
**Target State**: The LLM is prohibited from asserting a `[KNOWN]` claim unless it is accompanied by a **Fragment ID** from the ArangoDB Vault.
- **Implementation**: The `SovereignAnchor` skill must act as a gatekeeper. Any claim marked `[KNOWN]` must be cross-referenced against a hash in the `fragments` collection.
- **Code Logic**: 
  `IF claim == [KNOWN] AND NOT exists(fragment_id) THEN Trigger [SVR-RUPTURE: UNFOUNDED_CLAIM]`

### 2. From "Trying" to "Sovereign Spawning" (The Consensus Gate)
**Current State**: I attempt to reason through a problem in a single stream.
**Target State**: Use the **Sovereign Spawning** or **Cross-Model Debate Engine** to force divergent reasoning.
- **Implementation**: Implement a `SovereignDispatcher` that spawns $M$ independent model calls with distinct "Lenses" (Skeptic, Expert, etc.).
- **Deterministic Consensus**: The final output is generated by a non-LLM logic layer that compares the outputs of the $M$ paths.
- **The Rule**: Consensus is achieved only if $N$-of-$M$ paths produce identical core assertions.

### 3. From "Reporting" to "Artifact Proof" (The Sovereign Pulse)
**Current State**: I report progress in chat.
**Target State**: Every "Atomic Win" must be backed by a filesystem or database artifact.
- **Implementation**: The `SovereignPulse` system requires a `Proof_ID` (e.g., a git commit hash, a file checksum, or a DB entry) for every reported win.
- **Sovereign Audit**: A background process (or Soter check) compares the "Claim of Progress" against the "State of the Filesystem."

- [ ] **Dispatcher Logic**: Build the `SovereignDispatcher` to route queries to multiple Ollama Cloud models.
- [ ] **Consensus Algorithm**: Implement a string-similarity or semantic-overlap check to determine $N$-of-$M$ agreement without LLM "smoothing."

### Phase 3: Edge (The Audit Layer)

- [ ] **Provenance Exporter**: Create the "Sovereign Evidence" export tool for the Nexus, allowing external verification of the seal.

## ✅ Definition of Done (DoD)
1. **Zero-Trust Baseline**: A claim can be marked `[KNOWN]` if and only if it is anchored to a record in the ArangoDB Vault.
2. **Deterministic Consensus**: The system can prove that 3/5 different models reached the same conclusion for a specific technical claim.
3. **Artifact Verification**: The "Sovereign Pulse" can successfully detect a "lie" where a task is claimed "done" but no corresponding file change exists.
4. **Cryptographic Seal**: Every final output in SOL mode carries a seal that can be verified against the Sovereign Ledger.
